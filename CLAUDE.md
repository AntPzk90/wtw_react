# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

React port of the WTW ("What to Watch") app that was first built in `../wtw_nuxt`. The markup is split into template-only components and pages with hard-coded sample content; props, data fetching and state are still to be written, and `TODO` comments mark where. The user writes that code themselves, so act as a mentor (review, explain, hint) unless asked to implement. Update this file as things are added.

## Commands

npm is the package manager.

- `npm run dev`: Vite dev server at http://localhost:5173
- `npm run mock`: mock WTW API at http://localhost:3001 (port via `API_PORT`)
- `npm run build`: type-check (`tsc -b`) and build into `dist/`
- `npm run typecheck`: type-check only
- `npm test`: Vitest in watch mode; `npm run test:run`: run once (CI); single file: `npx vitest run path`
- `npm run lint`: ESLint + Stylelint + Prettier check (`lint:js`, `lint:style`, `format:check` run them one by one)
- `npm run lint:fix` / `npm run format`: auto-fix everything / only reformat
- Single file: `npx eslint path`, `npx stylelint path`, `npx prettier --check path`

## Architecture notes

- **Stack**: Vite, React 19, TypeScript 6 (not 7: typescript-eslint does not support it yet), React Router (`createBrowserRouter` in `src/router.tsx`, data-mode library, not framework mode).
- **Imports**: `@/` is `src/` (tsconfig `paths`, picked up by Vite through `resolve.tsconfigPaths`). Components use named exports.
- **Structure**: one folder per component and per page, named like the component: `src/components/<group>/<Name>/<Name>.tsx` (groups: `layout`, `catalog`, `movie`, `forms`, `player`, `ui`, `routing`) and `src/pages/<Name>/<Name>.tsx`. Styles, hooks or helpers that belong to one component go into its folder (`pages/NotFoundPage/NotFoundPage.css`). There are no `index.ts` barrels, so imports name the file: `@/components/layout/PageHeader/PageHeader`. Shared code gets top-level folders when it first appears: `api/`, `hooks/`, `store/`, `utils/`. BEM modifiers that depend on context (`movie-card__head`, `movie-card__poster--big`, ...) are passed from the parent as `className`.
- **Styles and icons**: `src/styles/main.css` is the built markup stylesheet, imported once in `App.tsx`; components use its BEM classes. It's excluded from Prettier on purpose. Icons are `<symbol>`s in `src/components/ui/SvgSprite/SvgSprite.tsx`, used as `<svg><use href="#id" /></svg>`. `public/img/` holds the markup images used by the static templates.
- **Buttons**: `ui/Button` (`<button>`) and `ui/ButtonLink` (router `<Link>`) add the base `.btn` class and pass all other props through; icon and text go in as `children`, modifiers (`btn--play`, `movie-card__button`) as `className`. `Button` defaults to `type="button"`. Buttons with their own block classes (`catalog__button`, `sign-in__btn`, `player__play`) stay plain `<button>`s.
- **Rating stars** (`RatingStars.tsx`): inputs and labels must stay direct siblings (use `Fragment`, not a wrapper), because the CSS paints stars with `:checked ~ .rating__label`.
- **Toasts**: `sonner`. `<Toaster>` is rendered once in `App.tsx`; call `toast.success()` / `toast.error()` from `sonner` anywhere. Colors are in `src/styles/toast.css`, wired through `toastOptions.classNames`.
- **Server data**: TanStack Query. `QueryClient` lives in `App.tsx` (defaults: `staleTime` 60s, one retry; a global `QueryCache.onError` shows an error toast; 4xx responses are neither retried nor toasted, pages show their own state, e.g. `NotFoundPage`). `queryFn`s call `request<T>(path, init?)` from `src/api/request.ts`, which throws `HttpError` (with `status`) on non-2xx (so don't `.catch` inside a `queryFn`), returns `undefined` on 204 and adds `X-Token` when logged in; `post<T>(path, body?)` (JSON-encodes the body) and `del<T>(path)` wrap it for mutations. Pages render `isPending` / `isError` / `data` directly. `QueryCache.onError` doesn't cover mutations.
- **Auth state**: Zustand, `src/store/useAuthStore.ts` (`token`, `user`, `setAuth(authInfo)`, `logout()`), saved to localStorage under `wtw-auth` by `persist`. `request` reads it outside React with `useAuthStore.getState()`; components use selectors. `routing/PrivateRoute` wraps auth-only pages in `router.tsx` (`/mylist`, `/films/:id/review`) and redirects guests to `/login` when `user` is null. `routing/GuestRoute` wraps `/login` and sends logged-in users to `/`. `PrivateRoute` passes `state.from`, and `SignInForm` returns there after login. All routes are children of `routing/RootLayout` (`<Outlet />` + `<ScrollRestoration />`); links that only change the query string (tabs, genres) use `preventScrollReset`.
- **Env**: `VITE_API_BASE` (see `.env.example`), read in `src/const.ts` as `API_BASE`.
- **Mock API** (`mock-server/server.mjs` + `mock-server/db.json`): same server as in the Nuxt project, a standalone Node server run separately from Vite. It implements the htmlacademy WTW endpoints, except that `/films` is paginated: `GET /films?page=1&limit=8&genre=Drama` (all optional, `limit` defaults to 8, max 50) returns `{ items, page, limit, total, hasMore }` instead of an array, and `/genres` lists all genres. Other endpoints: `/films/:id`, `/films/:id/similar`, `/promo`, `/favorite`, `POST /favorite/:id/:0|1`, `/comments/:id`, `/login`, `/logout`. Unmatched requests fall through to json-server, which also serves images from `mock-server/static/`. Auth is the `X-Token` header (base64 of the email); any email and non-empty password logs in. Image paths in `db.json` are relative to `mock-server/static/` (posters are external Wikimedia URLs) and responses turn them into absolute URLs. Review ratings are 1–5 stars; a film's own `rating` is on a 10-point scale. `isFavorite` is computed per user. POST requests write to `db.json`.
- **Tests**: Vitest (Jest-compatible API, `globals: true`, so `describe`/`it`/`expect`/`vi` need no imports) + React Testing Library + `@testing-library/user-event` + jest-dom matchers, in jsdom. Config is the `test` block in `vite.config.ts`; `clearMocks: false` on purpose, to behave like Jest (create `vi.fn()` inside each `it` or call `vi.clearAllMocks()` in `beforeEach`). Tests live next to the code as `<name>.test.ts(x)`. `src/test/setup.ts` loads jest-dom and resets `useAuthStore` and localStorage after each test. `src/test/render.tsx` exports `renderWithProviders(ui, { route, routes })`: a fresh `QueryClient` without retries plus a memory router; it returns `user` (userEvent) and `router` (check `router.state.location.pathname` after redirects). Network calls aren't mocked yet (no MSW).
- **Lint setup**: ESLint flat config (`eslint.config.js`): `@eslint/js`, `typescript-eslint`, `react-hooks`, `react-refresh` for `src/`, Node globals for `mock-server/`, `eslint-config-prettier` last. Prettier owns formatting (no semicolons, single quotes, width 100), same as the Nuxt project. `@ianvs/prettier-plugin-sort-imports` sorts imports into blank-line-separated groups: libraries, `@/pages` and `@/components`, other `@/` and relative modules, then `import type` (inline `type` specifiers are split out into it); config in `.prettierrc.json`. Stylelint extends `stylelint-config-standard` and enforces BEM class names; `src/styles/main.css` is excluded from Stylelint and Prettier on purpose.
